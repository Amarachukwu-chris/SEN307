# Lab 4 Notes: Referential Integrity (Week 6)

In Part 4, when I tried to delete the "Library and Information Science" department, MySQL returned **Error 1451: Cannot delete or update a parent row: a foreign key constraint fails**. MySQL refuses because `Student.dept_id` is a foreign key that references `Department.dept_id`, and the department was still the parent of one student (Transfer Student, `20239999`). Deleting it would have left that student pointing at a department that no longer exists (an orphan row), and the default foreign-key behaviour (`RESTRICT` / `NO ACTION`) blocks the delete to protect the integrity of the data. I fixed it the correct way in two steps: first I used `UPDATE Student SET dept_id = ... WHERE matric_no = '20239999'` to move the student to Software Engineering, so no student referenced the department any more, and then the `DELETE FROM Department` succeeded. The student was moved rather than lost, and the table was back to 5 departments. Another fix would have been to define the foreign key with `ON DELETE CASCADE`, which deletes the dependent student automatically (but silently destroys data), or `ON DELETE SET NULL`, which keeps the student but leaves them with no department (this needs `dept_id` to allow NULL). Deleting the student first would also have worked, but it loses the record.
